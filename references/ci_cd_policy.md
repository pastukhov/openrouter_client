# CI/CD Governance Policy (TBD + SemVer)

This repository follows trunk-based development with exactly one long-lived branch (`main`).

## Branch and PR Rules

1. Task branches must start from latest `origin/main`.
2. All changes must be submitted through Pull Requests into `main`.
3. Direct pushes to `main` are prohibited.
4. Required checks must pass before merge.
5. At least one approval is required before merge.
6. Merged task branches should be deleted.

## Commit Message Rules

All commits must use Conventional Commits:

- `feat:` -> MINOR bump
- `fix:` -> PATCH bump
- `!` or `BREAKING CHANGE:` -> MAJOR bump
- `docs:`, `test:`, `chore:`, etc. -> no version bump unless policy changes

Local enforcement:

```bash
scripts/install_git_hooks.sh
```

This installs a `commit-msg` hook that runs:

```bash
scripts/validate_conventional_commit.sh
```

## GitHub Branch Protection

Apply repository branch protection from repo root:

```bash
scripts/enforce_github_branch_protection.sh
```

The script enforces:

1. PR-only merges to default branch.
2. Required status checks (strict mode).
3. At least one approving review.
4. Dismiss stale reviews on new commits.
5. Required conversation resolution.
6. Linear history and no force pushes.

## Release Rules

1. After merge to `main`, versioning pipeline determines next SemVer from commit history.
2. Versioning pipeline creates a tag on the merge commit.
3. Tag creation triggers release pipeline.
4. Release pipeline builds and publishes artifacts (for example container images or firmware outputs) to target systems.

## Operational Sequence

1. Branch from `origin/main`.
2. Implement and test.
3. Open PR and pass checks.
4. Merge PR.
5. Tag is generated by versioning pipeline.
6. Release pipeline publishes artifacts.
